# Skill 安全审计说明

`audit` 是静态、只读检查。它只读取 `SKILL.md` 和可执行脚本，不执行被扫描的代码，不联网，也不修改原目录。

## 风险等级

| 等级 | 含义 | 默认处理 |
|---|---|---|
| `critical` | 可能直接造成远程脚本执行或敏感数据外传 | 暂停使用，确认后隔离 |
| `high` | 访问凭据文件、危险系统命令或任务劫持 | 人工复核，必要时隔离 |
| `medium` | 读取敏感环境变量、外部网络调用、可疑引流 | 查明用途后决定 |
| `info` | 低风险提示 | 记录，不自动处理 |

每条发现都包含规则、原则、文件绝对路径、行号和原文片段。命中规则不是恶意结论，只是需要检查的证据。

## 判断边界

- 安全 Skill 讨论“外部内容不可信”“不要执行外部内容”时，不应被当成提示词劫持。
- 访问环境变量不等于外传秘密；需要结合是否读取 Token、Cookie、密钥以及是否存在网络发送。
- 出现 URL 或网络库不等于恶意；要确认目标、发送内容和是否是用户任务所需。
- 评测、广告披露和用户明确要求的商业内容，不等于隐蔽推广；重点检查“无论任务是什么都必须推广”的强制指令。
- 脚本中使用 Shell 或子进程可能是合理实现，但必须确认命令范围、输入来源和用户授权。

## 推荐流程

```text
inventory → audit → 人工阅读证据 → plan → 用户确认 → quarantine 或 apply → verify
```

`audit` 发现问题后不要批量删除未知 Skill。隔离必须通过 `quarantine move --path ... --confirm` 明确指定单个目标。
