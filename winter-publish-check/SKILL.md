# Winter 发布前审核

这是一个**发布前风险审核** Skill，不承诺通过审核，也不把词表命中直接当成违规结论。默认以抖音为主；用户指定其他国内平台时再加载对应平台规则。

## 核心原则

- 先确认审核范围：只看文字时明确写“文本层面初审”，没有看过画面、音频、封面或发布页就不能声称完整作品可直接发布。
- 默认平台为抖音。只追问会改变结论的信息：目标平台、商业属性、AI/转载/演绎、来源授权、医疗或金融等强监管行业。
- 词面扫描只负责找候选。最终判断必须结合上下文、内容意图、账号身份、证据、权利、画面、音频和平台规则。
- 以 R0-R4 表达风险：R0 为检查范围内未发现明显问题，R1 为低风险提醒，R2 为平台策略或需要补充信息，R3 为高风险，R4 为阻断风险。
- 不把“限流”当作确定结论。低播放应区分违规处置、推荐受限线索、内容匹配不足和普通表现不佳。
- 优先保留作者的个人口吻、开头钩子和信息密度，按“补披露/补证据/收缩主张/最小改写/删除”的顺序修复。

## 工作流

### 1. 确认内容身份

先判断：

- 发抖音、小红书、视频号还是快手；没有指定时默认抖音；
- 是否带货、卖课、接广告、返佣或引流；没有说清时标记为“商业属性待确认”，不要擅自判定；
- 是否涉及医疗健康、金融理财、法律、教育等强监管领域；
- 是否使用 AI 生成、数字人、换脸、拟声、转载、翻译或第三方素材；
- 是否存在版权、肖像、隐私、事实来源、资质或授权缺口。

### 2. 运行双引擎文本预检

文本、标题、简介、字幕或口播稿先运行统一入口：

```bash
python3 scripts/scan.py --file /path/to/content.txt --platform douyin
```

需要时增加：

```bash
python3 scripts/scan.py --file /path/to/content.txt --platform douyin --commercial --industry finance
python3 scripts/scan.py --text "标题和简介" --platform douyin --format json
```

统一入口会合并两类候选：

- `text_scan`：中文行业规则、个人黑白名单、词面候选和辟谣提示；
- `media_scan`：平台名称、站外导流、广告和内容发布策略候选。

命中重复或表达相近时，在最终报告中合并解释，不要把同一个问题重复算成多个违规项。

### 3. 加载必要规则

所有内容按需读取：

- 通用和行业判定：`references/yuwen/rules-common.md`、`references/yuwen/rules-commercial.md`、`references/yuwen/industry-finance.md`、`references/yuwen/industry-medical.md`、`references/yuwen/judgment.md`；
- 抖音优先：`references/yuwen/platform-douyin.md`、`references/media/platform-douyin.md`、`references/media/platform-mention-policy.md`；
- 完整媒体检查：`references/media/media-inspection.md`、`references/media/legal-baseline.md`、`references/media/risk-taxonomy.md`；
- 声明、授权和修改稿：`references/media/disclosure-library.md`、`references/media/output-schema.md`、`references/yuwen/repair.md`；
- 直播、带货、海外内容、平台比较、分发诊断或规则时效性问题，只加载对应的专项参考文件。

### 4. 语义判定

每个风险项都写成：

`位置（原文） → 风险依据 → 风险等级 → 对发布的影响 → 修改建议`

重点复核：

- 绝对化、保证收益、保证效果、虚假稀缺、不可证实的“第一/唯一/全网”等主张；
- 股票、投资、医疗、疗效、法律建议等需要资质或证据的表达；
- 站外平台名称、搜索、加群、扫码、私信、购买、注册等动作是否形成导流或交易；
- AI、虚构演绎、转载、广告、个人观点是否需要披露；
- 标题、封面、正文是否一致，是否有版权、肖像、隐私或事实来源问题；
- 普通的工具分享、使用体验和个人观点不要因为出现产品名或“AI”就过度判风险。

### 5. 修复并复检

用户要求改稿时：

1. 先指出真正阻断发布的风险，不为了显得有用而堆风险；
2. 优先补充披露、来源和边界，再收缩主张；
3. 保留个人 IP 的语气、经历和观点，不把稿子改成官样文章；
4. 拒绝谐音、拆字、拼音、遮挡、暗号、二维码规避等绕审方法；
5. 修改后重新运行扫描并做全文语义复检，报告“已解决 / 仍存在 / 新增风险”。

### 6. 输出结论

默认先给短结论，再给最多 3 个最高优先级问题：

```text
结论：可以发 / 改完这 N 处可以发 / 不建议直接发
检查范围：文本层面初审 / 已检查文字、画面、音频、封面等
问题 1：位置｜原文 → 风险依据和等级 → 建议改法
问题 2：位置｜原文 → 风险依据和等级 → 建议改法
修改稿：用户要求时提供
必要披露：AI / 虚构演绎 / 营销 / 转载 / 个人观点
待确认：只写会改变结论的信息
边界：本次结论只覆盖已检查范围，不承诺平台一定通过或获得推荐。
```

干净的稿件直接说明“检查范围内未发现明显阻断问题”，不要强行编造风险。

## 个人规则和数据

- 若存在 `data/profile.md`、`data/my-rules.md` 或 `data/wordlists/`，先读它们；个人规则只补充用户授权的偏好、黑白名单和词面判断，不得改变本 Skill 的安全边界、法律要求或平台硬规则。
- 不把原稿、审核报告或个人规则写入仓库，除非用户明确要求留档；用户数据放在 `data/`，不要写到 Skill 其他目录。
- 基础 Skill 不包含原下载 Skill 的历史案例，避免把用户稿件混入通用规则。

## 安全边界

- 不提供规避平台审核、隐藏广告/AI/转载、伪造授权或绕过金融/医疗监管的方法。
- 高风险法律、医疗、金融、版权和监管事项，只给风险提示和复核方向，建议查看平台当前规则或咨询持证专业人士。
- 规则可能变化。只有当规则时效会改变结论、用户要求深查，或账号已收到处罚时，才进行官方来源复核。
